*A name is not a permission. In EOReader the two are enforced by different mechanisms entirely, and the Handle system is what the second one looks like when it is taken as seriously as the first.*

[Nine Instructions](/nine-instructions) makes the case that EO's contract system — `{ops, terrains, stances}`, narrowing downward, unioned upward, a logged `!REC` at every widening — is an effect system in the technical sense: permission tracked in a computation's own type. That argument is about what a module is *allowed to do*. It says nothing about what a module *is called*, who is answerable for it, or what happens when two people independently decide a domain needs a name. eoreader7's README answers that second question with its own piece of standing law: **Amendment XVII**, the Handle system (`README.md:250`).

## The rule, as written

> "One handle per organ or kernel module — the best-fitting historical or biological namesake, regardless of tradition. The ancestor is disclosed in a `// Handle: …` line at the top of the file itself; this table is the canonical index." (`README.md:252-254`)

Two enforcement points, not one. The namesake is declared *in the file*, at the top, where anyone reading the module sees it without consulting anything else — a repo-wide search turns up roughly 128 files carrying a `Handle:` disclosure in their own header comment. And it is indexed *once*, centrally, in the table that runs from `README.md:268` to `README.md:405`. Two copies of the same fact, checked against each other, is the same discipline [Holons](/holons) and [The Two Doors](/the-two-doors) both practice at the prose level — a claim is only as good as its anchor, and here the anchor is the file itself, not the index that describes it.

This is a naming system, not a permission system, and it is worth being precise about the difference. `eo-contract.js` (or its 4.2 ancestor; see [Holons](/holons)'s note that no live successor to that per-organ contract manifest has been re-confirmed in the current tree) governs what a module may *do*. The Handle table governs what a module *is called* and who — in the sense of which discipline, which tradition, which "best-fitting... namesake, regardless of tradition" — is accountable for how it does it. A module can lose its contract and keep its Handle; the two axes of governance are orthogonal, and eoreader7 runs both without collapsing one into the other.

## What one row actually promises

Reading the table as a flat list of clever names undersells it. Read as data, it makes four structural claims that a smaller or cleverer naming scheme would not have to make.

**A domain can span many files under one name.** `kernel/universal-grammar.js`, `kernel/eot-rich.js`, `adapters/text/english-parser.js`, and `adapters/text/clause-tense.js` are one row: Chomsky — "Principles are universal, parameters are set from little input; a grammar learned from what was heard reads what it never heard" (`README.md:359` in the Structure/kind/dynamics table). The same row discloses that Chomsky "also carries `eval/english/read-english.mjs` and the `eval/udhr/ug-*.mjs` family (declared, not yet in this table before now)" — the table's own text admitting, in real time, that the index had fallen a step behind the files it indexes. `activation-retrieval.js` / Kahanamoku (alias **Duke**) is the same pattern at a different domain: "Owns the whole surf: the frozen lexical surfer the doorway reads through, the doorway's `surfTask`/`contextForTask`, named activation (`activation-retrieval.js`), and the shadow/echo recall (`field-of-record.js`)" (`README.md:280`) — though it is worth flagging that on the current tree neither `activation-retrieval.js` nor `field-of-record.js` exists under its own name (checked against the full git history of both branches of this repo; neither path was ever committed), even though several other files (`native/eval/the-fold/conversation.mjs`, `holograph-compression.mjs`, `document-holograph.mjs`) import `activation-retrieval.js` from exactly that path. The domain and its owner are real and independently attested elsewhere (`native/organs/archon-compendium.js`'s Kahanamoku entry, wired through `proxy-runner.mjs::surfTask`); the two specific filenames the table prints for it are not currently backed by files under those names. `organs/run-dmca.js` / YadaYadaYada owns "the whole omnilingual paraphrase system (the shadow chase, the record equate, the witness's read, the Rosetta projection)" with a caveat worth keeping: "Alexander and Ranke still adjudicate the cells, but the domain has one owner" (`README.md:276`) — ownership of the domain does not evict the archons who already had standing inside it.

**One file can be duelled over by more than one Handle.** `the-fold/earned-cast.js` carries three rows: Terry Gross, Eastwood, and Kubrick (`README.md:303-305`). This is not decorative plurality — the file's own code resolves the duel mechanically. `earned-cast.js:182-188` comments the mechanism directly: "THE DIRECTORS DUEL OVER THE SHOT — Eastwood and Kubrick shoot the same scene two very different ways... The duel resolves by the scene: a big-picture ask (frame/map) is Kubrick's — composition is his; a tight exchange (escalation, a direct question) is Eastwood's — economy is his." The code backs the prose: line 181 routes `question`/`assertion`/`escalation`/`frame-ask`/`map-ask` acts through `push("terry-gross")`, and the surrounding logic branches Eastwood versus Kubrick by act shape. Three Handles, one file, and the dispatch between two of them is a real conditional, not a coin flip described after the fact.

**The same namesake can be reused for two unrelated files.** `kernel/scoped-kind.js` is Handle: Frege, "after the founder of quantification theory: a variable is bound within its quantifier's scope, and nowhere else" (`scoped-kind.js:16`). `organs/aliases.js` is also Handle: Frege, for an unrelated reason — "There is no real name: the Morning Star and the Evening Star are one object and two names... The referent IS the equivalence CLASS of its aliases" (`README.md:383`; see [Frege's Referent](/freges-referent-alias-equivalence-class) for the module itself). One historical figure, two files, two different Fregean ideas (bound quantification; sense-reference equivalence) borrowed for two different jobs. [Operator Naming in EO](/operator-naming-in-emergent-ontology) argues that every name in the framework is a *resonant signifier* rather than a definition — a pointer, not a proof. The Frege doubling is that doctrine holding at the file-Handle layer too: the table does not promise that a namesake is unique to a domain, only that it resonates with the specific mechanism it is attached to. That is a deliberate looseness, and it is worth naming as looseness rather than as an oversight, because a table that *did* enforce name-uniqueness would be making a stronger claim than eoreader7 actually wants to make about what a Handle is for.

**Some rows are reserved, honestly, for organs that do not exist yet.** The Pathos table lists Murch, Abhinavagupta, Panini, and Bharata against real, shipping files, then two more rows against no file at all: "proposed | Meyer | Tendency and inhibition — the felt deviation of what arrives from what was learned; the organ unbuilt" and "proposed | Shklovsky | Estrangement — perception prolonged against recognition; the organ unbuilt" (`README.md:315-316`). A repo-wide search for `meyer` or `shklovsky` under `native/` turns up two hits worth naming honestly, not zero. `native/organs/archon-compendium.js` — the separate module that credits every Handle's namesake — lists both, each tagged `organ: "organs/pathos.js (proposed)"`, the same not-yet-built status the README's table gives them, independently restated rather than assumed. `native/organs/essay-shape-register.js` borrows Meyer's concept by name ("Meyer's surprise, run on the register") for a different, already-shipped repair function — evidence the idea circulates in the codebase, not that the pathos.js row shipped. `organs/pathos.js` itself, the file the proposed row would extend, names neither Meyer nor Shklovsky. So the organ stays unbuilt in the sense the table means it; the more precise finding is two documents independently agreeing on "proposed" rather than a silent empty grep, and that agreement is the more interesting fact. The table names the gap before the code fills it, which is a different discipline than most naming registries practice: most either omit the unbuilt thing entirely (silent gap) or build a placeholder file just to have something to point the name at (premature commitment). eoreader7 does neither — it commits to the name and discloses the absence in the same line.

## Left plain, and the one file that earns its silence

Not every module gets a Handle, and the table says so without apology: "**Left plain** — no handle: `sequence`, `cite`, `web`, `fold`, `cube`, `artifact`, `assembly`, `task-log`, `cast-ledger`" (`README.md:393-394`). All nine files exist (`native/kernel/sequence.js`, `native/organs/cite.js`, `native/organs/web.js`, `native/kernel/fold.js`, `native/kernel/cube.js`, `native/kernel/artifact.js`, `native/kernel/assembly.js`, `native/kernel/task-log.js`, `native/kernel/cast-ledger.js`), and none of the nine carries a `Handle:` comment in its own header — the omission is real, not a table lapse. No justification is offered for any of the nine; they are simply infrastructure, and the doctrine implicitly treats "left plain" as its own legitimate category rather than an embarrassment to be backfilled with a namesake eventually.

`kernel/self.js` is different, and the README marks the difference explicitly rather than folding it into the same unnamed list: "`kernel/self.js` is left plain by design: it is not an organ but the reader's own ground — the identity born with every reader, frozen in the kernel, never a parameter, never a system prompt, and no surface can turn it" (`README.md:396-399`). The file's own header carries the same argument at length — it opens by distinguishing itself from every other module in the kernel: "Every other module in this kernel is a way of READING... This module is not a way of reading anything. It is what the reader IS" (`native/kernel/self.js:6-9`). This is the one load-bearing exception in the whole scheme: a module that is *excluded from naming on doctrinal grounds*, not merely un-gotten-to. Giving `self.js` a Handle would imply it is an organ among organs, swappable and namesake-able like `witness.js` or `what.js`. The README's insistence that it stay unnamed is itself doing governance work: it is the one place the naming convention is withheld in order to make a claim about what the file *is*, not merely what it does.

## The 2026-09-25 incident, now standing law

The Handle table's own preamble does not present itself as timeless. It opens with a dated failure and turns that failure into the rule that follows it:

> "**This table is a separate naming system from `archon-holocracy/archons.json`** (the worktree-scoped archon registry, a sibling repo alongside this one). A domain can be owned in one and absent from the other. Measured live, 2026-09-25: a session grepped only `archons.json` for literal keywords, found nothing, and proposed spawning a new archon for a domain (the English parser) this table had already named — Chomsky, row below — for some time. Before concluding any domain has no owner, check both: this table, and `archon-holocracy/archons.json`. See CODING-LESSONS.md #75." (`README.md:259-266`)

`CODING-LESSONS.md:1844-1879`, Lesson #75, gives the incident its full shape and its own measured number, not just the summary the README carries forward. A session had measured the English parser's real accuracy — "held-out LAS 77.0, confirmed live: locative-inversion and long participial-opening sentences genuinely mis-parsed, not just under-extracted" — and went looking for whose job it was to fix it. It grepped `archon-holocracy/archons.json` for three literal strings, found no match across 23 entries, and drafted a proposal to spawn a new archon. The domain was not unowned: Chomsky already covered `kernel/universal-grammar.js`, `kernel/eot-rich.js`, `adapters/text/english-parser.js`, and `adapters/text/clause-tense.js`, and a second Handle — Sullivan — already carried a wired second-witness role beside it, with an already-built, already-run measurement of parser accuracy on period-spelled English (`eval/lavar/period-parse.mjs`) directly on point for the failure class just discovered, and never consulted before the "unowned" claim was made.

The lesson's own diagnosis is the sentence worth keeping intact: "Both registries are real, both are checked by grep in practice, and a clean miss on one says nothing about the other — they are not mirrors of each other and neither table cross-references the other's existence... A miss in one registry is not a miss in both" (`CODING-LESSONS.md:1867-1879`). This is not a hypothetical failure mode written up for completeness. It is a dated, measured incident — a real accuracy number, a real grep, a real false "unowned" report — codified afterward into a standing rule cited by its own lesson number from inside the README that governs the very table the incident was about. Governance that can name its own failure and turn it into law without waiting for a rewrite is a stronger claim than a naming table that has simply never been tested. [Holons](/holons)'s discussion of this same incident calls it a naming-multiplicity failure "one layer down" from operator naming — here it is the mechanism working as designed: the two registries stayed real and stayed uncrossed, and the fix was a rule, not a merge.

## A second drift, undisclosed until now

The dual-registry incident is the failure eoreader7 already caught and wrote up. There is a second, smaller one still sitting in the table itself. The Belief/obligation/perspective table lists `kernel/notes.js` | Arokin | "Append-only record of what was said" as an ordinary, already-built row (`README.md:297`). Later in the same document, in the Left-plain section, the table adds: "`kernel/notes.js` (Arokin) is not yet built; the row above is reserved, not installed" (`README.md:404-405`).

That second claim is false against the current tree. `native/kernel/notes.js` exists, runs to 1,126 lines, and opens with its own Handle comment: "Handle: Arokin — after the Yoruba court historians, whose oral tradition kept an append-only record of what was said. Amendment XVII" (`native/kernel/notes.js:14`). It is not a stub — [The Two Doors](/the-two-doors) documents `notes.js` as the live ledger behind `witness()`, `attest()`, `dispute()`, and `standingOf()`, the mechanism that types a witness as `single-witness`, `corroborated`, or `corroborated-independently`. The README's own canonical index — the document whose entire premise is being the one place a domain's ownership can be checked without guessing — is stale about the build status of one of its own rows. This is exactly the deserved companion finding to Lesson #75: the dual-registry incident showed that two *separate* documents can miss each other; this shows that a *single* document can miss itself, one section forgetting what an earlier section already recorded as done. Disclosing it here rather than quietly not mentioning it is the same discipline [The Two Doors](/the-two-doors) applies to its own retracted claims — a documentation drift is not a scandal, but it is a fact, and the wiki's practice is to say so rather than to let the more flattering half of the document stand uncorrected.

## What Handles are actually for

Put the four structural claims and the two incidents together and the Handle system reads less like an easter-egg layer of colorful names and more like an accountability register running parallel to, and independent of, the contract system [Nine Instructions](/nine-instructions) describes. The contract system asks *what is this module permitted to do*. The Handle system asks *what tradition of thought is this module's design accountable to, and who owns this domain when two people reach for it at once*. Both are enforced the same way — declared locally, indexed centrally, checked against drift — and both have already produced a dated, measured failure that became codified law rather than an embarrassment papered over. A framework that can catch its own naming system lying to itself, twice, in the same document, and say so in public, is treating names as load-bearing rather than as color. The Handle name is never the point. The doctrine it discloses — narrow ownership, checkable in two independent places, honest about the rows it has not built yet and, it turns out, about the rows it forgot it had — is.
