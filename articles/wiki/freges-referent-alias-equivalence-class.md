*The Regional Transit Authority and the RTA are one thing and two names. The question a reader has to answer is never "which name is real" — it is "what makes two names the same."*

## The hole, stated exactly

`native/adapters/text/surfaces.js` already folds one common kind of coreference: a name shortened by dropping words. Run it directly:

```
namesCorefer("Regional Transit Authority", "Transit Authority") -> true   // surfaces.js:132
namesCorefer("RTA", "Regional Transit Authority")                -> false // surfaces.js:132
```

Both calls are real, run against the checked-in module, not reconstructed from a comment. `namesCorefer` folds a dropped-words shortening and refuses an initialism outright — not as a bug, but because the function has no rule for initials at all. `native/organs/aliases.js` opens by naming this precisely: "a name shortened by INITIALS is not folded at all" (`aliases.js:1-8`). That gap is the module's whole reason to exist.

## The refused fix, and why it is refused

The obvious patch is small: build an initialism from capitalized words and compare it against candidate short forms. `aliases.js` states the fix and then declines it in the same breath:

> "The tempting fix is a rule that builds an initialism and compares it. This module deliberately does not do that, for the reason the whole project keeps re-earning: a rule that derives a name is a rule that can INVENT one, and 'the same referent' has never been safe to decide from the shape of a string." (`aliases.js:11-16`)

This is the actual doctrine, and the Handle name the module carries — Frege, "there is no real name" (`README.md:383`) — is color for it, not the content. The content is narrower and more mechanical than the philosophy of language it borrows from: **a structural rule (capitalization, length, a regex over letters) is never allowed to manufacture identity.** Only the material's own declaration can. Where `namesCorefer` already has this discipline built in for token-dropping (it requires a caller-injected `commonNoun` witness before it will let a single bare token corefer with a longer name — "an ordinary personal name is not also an ordinary common noun," `surfaces.js:145-154`), `aliases.js` extends the same discipline to the one shape `namesCorefer` cannot reach at all: the initialism.

So instead of inferring sameness from spelling, the module reads for a *declaration*. English prose that introduces a short form almost always glosses it once, at a specific place: "the Regional Transit Authority (RTA)." Reading that gloss is treated as the same kind of act as reading any other claim in the material — "nominate structurally, wall against the bytes, keep the address" (`aliases.js:25-26`). An initialism turns out to be one subtype of alias among several the same mechanism catches for free — a nickname, a stock ticker, a d/b/a, a case caption — and the module states plainly that it does not privilege any of them: "Nothing here knows what an acronym is" (`aliases.js:28-29`). The test suite encodes exactly this case: one test feeds the mechanism "the Riverside Housing Trust (the Trust)," a gloss that shares no letters with its initials at all, asserting it is admitted on exactly the same evidence path as RTA (`aliases.test.mjs:30-37`). That assertion does not execute in this checkout — like the rest of `aliases.test.mjs`, it is skipped because the sibling `live_priors` repo isn't present (see below) — so it was re-run here directly, with a hand-built parenthetical-gloss shape standing in for the measured one: the non-initial gloss is admitted on the identical evidence path as RTA, confirming the claim independently of the test suite's own unexecuted run.

## Where the shapes come from, and what the number actually says

`aliases.js` does not carry its own idea of which glosses look like declarations. It receives a measured prior — `AliasDeclarationPrior@1` — built by a sibling project, `live_priors`, over real prose, and the module's `shapesFrom()` function does nothing but filter that prior against floors the caller supplies (`aliases.js:65-91`). The prior itself is not in this checkout: `aliases.test.mjs` looks for it at `../../../live_priors/derived-priors/alias-priors/alias-declaration-en.json` and skips its own tests when the sibling repo isn't present (`aliases.test.mjs:13-16`) — which is the case in this environment. Every one of the suite's eleven tests carries this same skip condition, confirmed by running the file directly (`node --test aliases.test.mjs`: 11 skipped, 0 run); where a specific test is cited below as independently verified, that verification was run directly against the module rather than through that suite. The number below is therefore **asserted in the module's own source comment, not independently re-derived here**:

> "Measured over 900 files / 20.8MB: the parenthetical fires 23,375 times at a 0.478 confirm rate; 'also known as,' 'abbreviated,' 'd/b/a' and the rest fire in the single digits or never." (`aliases.js:35-37`)

Read that plainly: a *confirmed* rate of 47.8% means that more than half the time English prose opens a parenthetical after a proper name, it is not declaring an alias at all — it's a date, a citation, an aside, a qualifier. This is disclosed as a limit, not smoothed over: the parenthetical is common and unreliable at the same time, which is exactly why `aliases.js` does not treat "looks like a gloss" as sufficient and adds a second, independent gate on top of it (below). The comparison the comment volunteers is a negative result on the alternative shapes — "also known as," "abbreviated," "d/b/a" barely fire in real prose at all — and the test suite pins that negative finding as a first-class assertion, not a stray note: `shapesFrom` is written to *not* return a shape called `"short-for"` even when the floor is generous, "because it never fired in the corpus," asserting the prior's own record for that shape reads `fires: 0` (`aliases.test.mjs:75-81`) — an assertion that, like the rest of that suite, does not execute in this checkout, so the `fires: 0` figure is sourced to the test's own code, not independently re-derived here. A framework that will assert a real number should also be willing to name the shapes that measured at zero, and this module does both in the same file.

## The wall: declaration is necessary, use is what makes it a name

A single gloss is not enough on its own, even a well-formed one. `aliases.js` adds a second, independent requirement: the alias must actually recur in the material — `minUses`, "the declaration itself counting as one" (`aliases.js:41-44`) — before the gloss is admitted. A name introduced and never used again is a throwaway aside, not a name the text is using, and it is returned as a *typed refusal* rather than silently dropped: `ALIAS_REFUSALS.USED_ONCE` (`aliases.js:57-63`; the identical case is asserted at `aliases.test.mjs:39-44`, though — like the rest of that suite — it is skipped in this checkout; re-run directly against the module with a hand-built gloss shape, the same refusal fires).

The module does not pick the number itself. `declaredAliases` throws if the caller omits `minUses`, with a message that states the refusal to decide as policy: "how often a gloss must recur before it is a name is never a constant chosen here" (`aliases.js:110-111`). What the module does instead is point at precedent. Its own comment claims the floor "wherever recurrence has to mean anything" across this codebase converges on 2 (`aliases.js:44-46`) — and that claim checks out against the constants that can be checked directly. Two of those are named constants, independently defined in two different organs, at the same value, for the same reason each states explicitly: `WITNESS_FLOOR = 2` in `native/organs/asserted.js:126` and `FORM_MIN_ARRIVALS = 2` in `native/organs/hypergraph.js:215`, one occurrence having nothing to be compared against. `asserted.js`'s own comment further attributes the identical floor to `emergence/binding.js`'s arrivals gate ("binding's structural minimum," `asserted.js:42,123`) — but `binding.js` does not carry it as a single named constant the way the other two organs do; it repeats the equivalent `totalUnits < 2` refusal inline at each of its four public entry points (`binding.js:305,386,445,509`), the same floor enforced the same way, just not spelled out as its own constant. `aliases.js` doesn't hardcode 2 either — but every caller in the test suite that exercises it does (`aliases.test.mjs:18`, `const MIN = 2`), which is the discipline converging on itself rather than a shared constant enforcing it.

Every admitted alias also carries the sentence that declared it and that sentence's own byte span, re-read from the source text before being returned (`aliases.js:50-52`, `147-148`) — the same address-verification discipline named "P5.2" elsewhere in this codebase and the same posture as `native/kernel/witness.js`'s refusal to admit a candidate that isn't anchored to the actual encounter (see [The Two Doors](/the-two-doors)). An alias here is evidence, not metadata: it is citable, and the citation is checked, not just attached. `aliases.test.mjs:101-109` encodes exactly this failure mode — feed `declaredAliases` a sentence splitter that returns text without offsets — though, like the rest of that suite, it does not execute in this checkout. Re-run directly against the module: every alias that offsetless splitter would otherwise let through is refused instead, tagged `ADDRESS_UNVERIFIED`.

## The equivalence class: no privileged spelling, ever

This is the part of the module that earns its Handle. Once a text has declared some pairs of forms coreferential, `aliasClasses()` does not pick a "real" name and treat the rest as its nicknames. It runs a deterministic union-find over every declared pair, folding each full/alias gloss into the same disjoint set no matter which side of the parenthesis it came from (`aliases.js:188-217`). The module's own comment states the reasoning it is refusing to violate:

> "There is no real name; the referent is its class of aliases... The text declared that two forms are one thing — the 'full' form ... is the gloss's LEFT side, not a truth; the initialism is the gloss's RIGHT side, not a nickname. Both are ALIASES." (`aliases.js:175-182`)

This is checkable, and it checks out. Running `aliasClasses()` against a gloss written full-then-alias, and separately against the same pair written alias-then-full, produces the identical class key both times (`67dd1d4f` in a direct run against this checkout) — order of declaration carries no information about which form is more real. The class carries a `display` form for convenience, and the module is explicit that it is arbitrary: the byte-least of the class's forms, "for display only — it is not a name" (`aliases.js:211`). The identity that actually travels downstream is `classKey()` — a byte hash over the whole sorted class, joined with a NUL byte, order-independent by construction (`aliases.js:219-226`) — never a spelling. Two different texts that happen to gloss the same pair of forms reach the same key without either one agreeing on which form is "the" name, because neither text's agreement was ever the mechanism.

That key is what `aliasClassMap()` hands to the surface layer: a form-to-class-key index consumed by `referentIdentity()` in `surfaces.js:524-531`. Read its own comment: "the identity of the thing NAMED, not of the spelling... there is no real name: the referent IS its class of aliases. Otherwise the identity is the canonical BYTES." This is the whole doctrine landing in one function signature — an alias resolves through the class when one exists, and only falls back to the byte-identity of a single spelling when the text never bothered to declare anything at all.

## Distinct from operator naming — a real distinction, not a caveat

The wiki already has a doctrine that sounds like this one and is not: [Operator Naming in EO](/operator-naming-in-emergent-ontology)'s account of "resonant signifiers," worked out through the position-two operator's rename from Designation to Distinction to (proposed) SIG. That article's claim is that EO's own vocabulary — operator names, Greek letters, glyphs — never *defines* the structural position it points at; the position (a Mode × Domain coordinate in the capacity ground) is independently verified across more than a hundred domain-specific systems and exists whether or not it has a label at all.

`aliases.js` is not that claim, and the difference is worth stating plainly rather than eliding. The operator article's positions are prior to and independent of any name given to them — that is what the hundred-tables convergence argument is *for*. `aliases.js` has no such independent access to a referent. It cannot see the Regional Transit Authority; it can only see what the material says about it. The equivalence class it builds is minted entirely from the text's own declared sameness — there is no structural coordinate underneath it the way there is under SIG. So where the operator-naming article's moral is "the position is real, the names are approximations of it," `aliases.js`'s moral is narrower and, if anything, more skeptical: *there is no independently-accessible referent at all, only the class the material was willing to assert.* Citing Frege for the Morning Star and the Evening Star gestures at a real external object (Venus) that both names track; `aliases.js` never claims that much. It claims only that when a text asserts two forms are the same, no downstream rule gets to un-declare that assertion by treating one of the forms as more authoritative. That is a smaller, more defensible claim than the philosophical one its Handle borrows, and the module is better for making the smaller one.

## What this buys, and what it does not

What it buys: an initialism, a nickname, a d/b/a and a case caption are all admitted through one evidentiary path, gated by a measured prior with a disclosed 47.8% false-fire rate on its most common shape and a recurrence wall shared with two other real constants in the codebase — and every admission is byte-addressable back to the sentence that made it. What it does not buy: any claim about the world outside the text. Two texts that never gloss a pair of forms at all get two different byte-identities for what might, outside the document, be the same organization — `aliases.js` has no opinion on that, because forming one is exactly the kind of inference-from-shape it was built to refuse.
